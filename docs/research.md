# ПотужнийСкрипт: дослідження

Дата: 01.11.2026. Стан: перша версія працює — `src/`, `bin/potuzhno.ts`, тести в `test/`, TypeScript без збірки.

## Коротко

- **Підхід:** `.potuzhno` — це звичайний JS, у якому мемні слова стоять замість ключових слів і назв. Перекладач розбиває файл на токени, замінює мемні слова на JS-слова за словником і віддає результат Node. Власного парсера чи інтерпретатора не треба: кирилиця в іменах легальна для JS, тому мемний код уже лексично валідний.
- **Обсяг ядра:** ~20 рядків на `js-tokens` + `magic-string` + вбудований у Node хук `module.registerHooks`. Прототип запустився на Node 26.13: `node --import ./hooks.mjs t.potuzhno` працює, а помилка вказує на рядок і стовпець у самому `.potuzhno`.
- **Головна робота — словник.** Нижче чернетка на 152 слова: усі ключові слова, значення (`true`, `null`…), глобальні об'єкти та їхні основні методи.
- **Схожий проєкт є лише російський:** YoptaScript (2,2 тис. зірок), та сама ідея на гопницькому сленгу. Української мемної мови поверх JS немає. Назва `potuzhno` в npm вільна.
- **Апостроф:** в іменах JS працює лише `ʼ` (U+02BC). Звичайний `'` відкриває рядок, а `’` (U+2019) дає синтаксичну помилку. Перевірено в Node 26.13.

## Як це працює

```
файл.potuzhno ─► js-tokens ─► мемне слово? → JS-слово ─► magic-string ─► JS + source map ─► Node
                 (токени)       (словник)                  (заміна)
```

- Рядки, коментарі, регулярні вирази й текст шаблонних рядків не чіпаємо. Код усередині `${…}` перекладаємо: `js-tokens` правильно розбирає вкладені шаблони та відрізняє ділення від регулярного виразу.
- Переклад іде в один бік, мем → JS. Англійський JS у `.potuzhno` теж працює, тому npm-бібліотеки з англійським API можна викликати без змін.
- Запуск: хук `load` з `module.registerHooks()` перехоплює файли `.potuzhno` і віддає перекладений код як ES-модуль. Так само працюють `tsx` і `@swc-node`. `module.register()` не беремо: у Node 26 він застарів (DEP0205).
- `node --enable-source-maps` показує в помилках рядок і стовпець `.potuzhno`. Самі тексти помилок V8 лишаються англійськими (див. «Пастки»).

## Правила перекладу

1. **Токен у токен.** Одне мемне слово — одне JS-слово. Тому `catch` у `try/catch` і в `обіцянка.catch()` мають те саме слово (`набу`), `delete` як оператор і `map.delete()` теж (`люстрація`). Розрізняє їх сам JS. Кілька мемних синонімів для одного JS-слова дозволені, бо переклад однобічний.
2. **Назви властивостей перекладаються всюди.** `obj.розпил` стає `obj.map`, а `{ розпил: 1 }` — `{ map: 1 }`. Усередині `.potuzhno` усе узгоджено. Ламається лише на межі з чужими даними: JSON з ключем `"розпил"`, доступ рядком `obj["розпил"]`. Для першої версії це найпростіше правило, YoptaScript працює так само.
3. **Рядки не перекладаються.** `typeof x === "string"` лишається англійським.
4. **Зарезервовані лише слова ключових слів.** Змінна `відкат` стане `return` і дасть синтаксичну помилку. Змінна `розпил` стане `map` і просто працюватиме.
5. **Апостроф.** У словнику `ʼ` (U+02BC). Перекладач зливає `імʼя`, набране через `’`, у правильне слово. Звичайний `'` у JS відкриває рядок, тому його не підтримуємо, і про це буде в документації.
6. **Власні імена — латиницею** (рішення Максима, 01.11.2026). Кожне кириличне ім'я, якого немає в словнику, перекладач транслітерує за постановою КМУ №55 (2010): `Депутат` → `Deputat`, `бюджет` → `biudzhet`, `імʼя` → `imia`, `ЩУКА` → `SHCHUKA`. Згенерований JS — лише ASCII, тож англійський JS може імпортувати `.potuzhno`-модулі. Латиниця залежить лише від самого імені, не від файлу, тому імпорти між модулями збігаються. Якщо латиниця — зарезервоване слово чи глобальний об'єкт, додається `_` (`до` → `do_`, `Сет` → `Set_`). Два різні імені з однаковою латиницею (`кут` і `куть` → `kut`) — помилка з рядком у файлі.

7. **Слова-оператори зарезервовані.** Для `+ - * / %` у словнику є мемні слова (`донат_на_дрони`, `відпил_бюджету`, `тиражувати_обіцянки`, `ділити_по_братськи`, `залишок_після_розпилу`). Ціль запису тут — символ, тому такі слова не можна взяти як імʼя змінної чи властивості: `obj.+` не JS. Слова обрано мемні й довгі, щоб не збігатися з побутовими «помножити» чи «залишок», які програмісти справді називають змінні. Перекладач додає пробіл між словом-оператором і сусіднім символом, інакше `відпил_бюджету-1` стало б `--1`, а `ділити_по_братськи/б` — коментарем `//б`.
8. **Одне JS-слово — один мем.** Переклад токен у токен, тому `add`, `remove`, `get`, `length`, `value`, `type` мають одне мемне слово для всіх обʼєктів, що їх мають. Словник живе в `src/dictionary/entries/` (файл на область), `meme-entries.ts` лише збирає їх. Повноту стандартної бібліотеки Node і щоденного DOM перевіряють `test/dictionary/standard-library-coverage.test.ts` та `dom-coverage.test.ts`; усе, що навмисно не покрито (Annex B, застарілі API, потоки), записано там у виключеннях із причиною.

9. **Регулярний вираз після мемного слова.** Токенізатор вирішує «регулярний вираз чи ділення» за попереднім токеном і знає лише англійські слова: після `відкат` він читав «/» як ділення, і слова всередині регулярного виразу (`/потужно/`) перекладалися, а лапка в ньому ламала решту файлу. Тому `IdentifierScanner` перед «/» після слова-виразу (return, typeof, new, await…) чи слова-оператора запускає лексер заново з цього місця. Межа: `щоб (умова) /re/` і «/» усередині `${…}` не виправляються.

## Що покриваємо з JS

Перша версія — усе з таблиць нижче:

- **Ключові слова:** оголошення (`let`, `const`, `var`), функції, класи, модулі, умови, цикли, `switch`, винятки, `async/await`, оператори-слова (`typeof`, `instanceof`, `in`, `delete`, `new`).
- **Значення:** `true`, `false`, `null`, `undefined`, `NaN`, `Infinity`, `globalThis`.
- **Глобальні об'єкти:** `console`, `Math`, `JSON`, `Object`, `Array`, `String`, `Number`, `Boolean`, `Map`, `Set`, `Promise`, `Date`, `Error`, таймери, `fetch`.
- **Методи:** основні методи масиву, рядка, `Object`, `Map/Set`, `Promise`, `Math`, `JSON`.

Не покрито: `Intl`, `Atomics`, `WebAssembly`, CommonJS (`require`), потоки (Streams API), `Buffer`. Решта стандартної бібліотеки й щоденний DOM у словнику є.

```js
const VIDKAT = 0.1;
let biudzhet = [100, 200, 300];

function rozpylyty(suma) {
  return suma * VIDKAT;
}

class Deputat extends Object {
  constructor(imia) {
    super();
    this.imia = imia;
  }
}

let vidkaty = biudzhet.map(rozpylyty);
console.log(`Відкати: ${vidkaty.join(", ")}`);

let sizo = new Set();
try {
  if (vidkaty.reduce((a, b) => a + b, 0) > 50) {
    throw new Error("Забагато відкатів");
  } else {
    console.log("Схема чиста");
  }
} catch (e) {
  sizo.add(new Deputat("Петренко"));
  console.error(e.message);
} finally {
  console.log(`У СІЗО: ${sizo.size}, вийшли під заставу`);
}
```

## Пастки

- **Підрядки.** YoptaScript спершу перейменовував частини імен функцій (issue #65), бо замінював текст. Ми замінюємо цілі токени, тому `потужностанція` лишиться як є.
- **Словник старіє.** У YoptaScript просили методи ES2023 (issue #436). Потрібен тест: кожна ціль словника існує в JS як ключове слово або як властивість вбудованого об'єкта. Інший тест — що мемні слова не повторюються.
- **Межа з чужими даними.** `obj["розпил"]`, JSON із мемними ключами, англійський код, який читає перекладені ключі (`{ розпил: 1 }` → `{ map: 1 }`).
- **Тексти помилок англійські.** Source map дає правильні рядок і стовпець, але V8 пише «x.map is not a function». Переклад повідомлень назад у меми можна зробити через `Error.prepareStackTrace` і таблицю, але це окрема фіча, не для першої версії.
- **Однакова латиниця.** `кут` і `куть` дають `kut`, бо `ь` при транслітерації зникає. Перекладач зупиняється з помилкою, а не перейменовує мовчки.
- **Латиниця в результаті.** Ключі обʼєктів у `JSON.stringify` і назви функцій у стеках — уже латиницею (`imia`, `biudzhet`), бо власні імена транслітеруються.
- **Зарезервовані слова.** Змінна з назвою мемного ключового слова ламає синтаксис. Короткі слова (`в`, `з`, `як`) часто трапляються в коді, тому перекладач має пояснювати таку помилку.
